## HAMi 실험 요약 (2026.9.2 ~ 10.7, 5회)
 
장비: RTX 4080 SUPER, RTX 3060, RTX 2060 SUPER, RTX A6000 ×2 (서버 4대) / 드라이버 580, HAMi-core `f01e9f23`, Docker 단독(Kubernetes 없음)
 
### 검증한 가정
"물리 GPU 한 장을 여러 개의 격리된 몫으로 나누어 각 몫에 VRAM 상한을 강제할 수 있고, 그 안에서 실제 딥러닝 작업이 정확하게 실행되며, 한 사용자가 다른 사용자의 작업을 망가뜨릴 수 없다."
 
### 결론 요약
- **분할·강제·정확성·작업 격리: 성립.** 상한 초과 할당은 잡을 수 있는 OOM으로 거절되고, 실제 작업 5종(ResNet-18/50, BERT, GPT-2, SD 1.5)이 분할 상태에서 비트 단위로 같은 결과를 냄. 가로채기 비용 1 % 미만. 어떤 이웃도 다른 사용자의 결과를 바꾸지 못함.
- **몫 크기 계산: 노드 등록 시 보정 필수.** 몫 하나의 고정 비용(컨텍스트)은 카드마다 다르고 `26 MiB + 1.87 KiB × (SM 수 × SM당 최대 스레드)`로 예측됨(A6000 사전 예측 261.6 → 실측 262). VRAM 용량과는 무관. 일괄 규칙 "설정값 − 256"은 A6000(손실 352 MiB)에서 깨짐.
- **다중 사용자:** 같은 작업 9명까지 성능이 1/N로 고르게 나뉘고 카드 처리량 99 % 유지. 수용 인원을 정하는 것은 메모리. 성격이 다른 작업을 섞으면 긴 커널을 쌓는 작업이 GPU 시간을 더 가져감.
- **두 장 카드:** 장치별 상한·차감이 독립적으로 동작, 두 장 분산 학습(DDP) 결과 비트 일치, 처리량 손실 1.3~1.7 %.
- **여러 노드:** 이기종 두 노드를 하나의 풀로 운용, 동시 요청 폭주·연결 끊김·실행기 교체에서 과할당·회수 누락 없음.
- **VRAM 용량 격리: 성립하지 않는 경로가 있음.** 사용자 코드 한 줄로 몫 바깥 물리 메모리를 몫의 수 배까지 점유 가능(A6000에서 2g 몫이 약 10 GB).
### 확인된 결함과 대책
1. **몫 바깥 물리 점유 (가장 중요)**
   - 원인: HAMi는 할당 API만 가로채므로, 드라이버가 컨텍스트 안에서 잡는 메모리(스레드별 스택 예약, 커널 코드 적재 등)를 보지 못함. `cudaDeviceSetLimit(cudaLimitStackSize, 64K)` 한 줄로 A6000 2g 몫이 10,010 MiB(×4.9), `CUDA_MODULE_LOADING=EAGER`로 +944 MiB. 큰 지역 배열을 쓰는 직접 짠 커널은 호출 없이도 생길 수 있음(미측정).
   - 대책: ① 호스트에서 컨테이너별 물리 사용량을 감시해 초과 시 종료 ② 배정 차감을 `max(설정값 + 여유분, 실측 물리 사용량)`으로 계산 ③ 보조로 HAMi-core에서 `cuCtxSetLimit` 가로채기 ④ `CUDA_MODULE_LOADING=LAZY` 강제. 검증 전까지 "용량 격리 보장"을 "할당 API 기준 상한 보장"으로 표기.
2. **몫 크기 일괄 규칙이 큰 카드에서 틀림**
   - 대책: 노드 등록 시 보정(카드당 약 30초)을 필수로. `배정 차감 = 설정값 + 여유분(최소 64 MiB)`, 사용자에게는 `설정값 − 워밍업 뒤 손실`을 표시. 카드 모델 + 드라이버 + 이미지 단위로 저장.
3. **환경변수만으로 주입하면 상한 우회**
   - 대책: `/etc/ld.so.preload`에 읽기 전용 주입(검증됨). 사용자에게 관리자 권한 부여 불가.
4. **비동기 할당자(`cudaMallocAsync`)에서 CUDA 그래프 캡처 실패**
   - 대책: 이미지에서 할당자 설정을 기본값으로 고정(검증됨).
5. **동시 시작 경합 (1회 발생, 재현 안 됨)**
   - 대책: 노드별 시작 간격 1초, 시작 30초 안 OOM은 1회 재시도.
6. **장치별 상한 지정의 함정 (두 장 카드)**
   - `CUDA_DEVICE_MEMORY_LIMIT_<i>`만 주고 공통값을 빠뜨리면 지정하지 않은 장치는 상한 없음. `<i>`는 컨테이너 안 순번.
   - 대책: 컨테이너에 보이는 모든 장치에 상한 명시, 한 장 배정은 `--gpus device=<n>`으로 그 장치만 노출.
7. **HAMi 초기화가 장치 0을 건드림 (미확인)**
   - 두 장 DDP에서 rank1이 장치 0에 최대 210 MiB를 남김.
   - 대책(잠정): 두 장 이상 컨테이너는 확인 전까지 같은 서버 장치를 함께 비워 배정.
8. **섞인 작업의 GPU 시간 쏠림**
   - 연산 제한(`SM_LIMIT`)은 커널 실행 직전에만 개입해, 이미 실행된 긴 커널은 막지 못함(10 % 설정에도 큰 행렬곱은 32 % 사용).
   - 대책: 쏠림 완화용으로만 쓰고 공정 배분을 보장한다고 안내하지 않음. 같은 과제는 같은 카드에 모아 배치.
