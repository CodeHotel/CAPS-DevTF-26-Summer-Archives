## 요약
이번 조사는 외부 사용자가 교내 GPU 서버에 접속하고, 작업 컨테이너에서 NAS에 학습 파일을 저장할 수 있는지 확인하기 위해 진행했습니다.
MVP의 외부 접속 방식으로는 GPU 서버가 EC2에 SSH 역방향 터널을 열고 사용자가 EC2를 거쳐 접속하는 구성을 권장합니다. 이 경로에서 EC2와 GPU 사이의 평균 왕복 시간(RTT)은 약 4ms로, 기존 중계 서버를 거칠 때의 약 9ms보다 짧았습니다. GPU에서 EC2로 데이터를 보내는 속도도 약 85Mbps에서 93Mbps로 높아졌습니다. NetBird로 노트북과 GPU2를 직접 연결해 SSH로 로그인할 수 있었지만, GPU2에서 노트북으로 파일을 내려받는 동안 수신이 여러 차례 멈췄습니다.
GPU1과 GPU2는 같은 공유기를 통해 최대 100Mbps의 인터넷 연결을 나눠 씁니다. 두 서버가 동시에 EC2로 데이터를 보낼 때 합산 속도는 평균 92.73Mbps였습니다. 같은 공유기에 GPU 서버를 추가해도 외부 전송에 쓸 수 있는 전체 대역폭은 그대로입니다. 노트북에서 GPU1의 파일을 내려받는 동안에는 같은 터널의 평균 RTT가 약 12ms에서 184ms로 늘었습니다. 파일 전송이 SSH 사용에 미치는 영향을 줄이기 위해 SFTP 속도를 연결당 약 16Mbps로 제한해 테스트한 결과, SSH 명령 실행 300회와 새 로그인 48회가 모두 성공했습니다.
학습 파일은 GPU 서버에서 교내 NAS에 SMB로 직접 연결해 읽고 쓰는 구성을 권장합니다. GPU1, GPU2, A6000 모두 NAS의 SMB 포트에 접속했고, GPU1과 GPU2에서는 개발용 폴더를 마운트해 파일 생성부터 읽기, 쓰기, 삭제까지 확인했습니다. 두 서버가 각자 128MB 파일을 동시에 쓰고 읽는 테스트를 세 번 반복한 결과, 평균 합산 속도는 쓰기 11.11MB/s, 읽기 11.39MB/s였습니다.
MVP에서는 교내 관리 프로그램이 HTTPS로 EC2에서 작업 환경 생성과 종료 요청을 받아 처리합니다. 사용자는 EC2의 SSH 역방향 터널을 통해 자신의 컨테이너에 접속하고, 학습 프로그램은 EC2를 거치지 않고 NAS의 파일을 읽고 씁니다. 남은 작업은 이 구성을 실제 컨테이너에 적용해 사용자마다 자신의 작업 환경과 폴더에만 접근할 수 있는지, 작업 환경을 종료한 뒤에도 파일이 보존되는지 확인하는 것입니다.
